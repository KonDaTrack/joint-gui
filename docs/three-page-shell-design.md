# 子系统 1：页面外壳 —— 设计文档

**日期**：2026-10-09
**状态**：已实现（外壳）；组态页与初始页随后一并实现，见 §9
**范围**：`joint-gui/web/` 的页面框架、常驻安全条、页面切换、文件拆分
**上游**：`host-embedded-architecture.md`（协议与控制权）

---

## 1. 背景

现有网页上位机是**单页仪表盘**：一张屏上同时挤着关节列表、读数、操作、目标、波形。
信息密度低（目标卡片下半约 180px 常年空白），且没有扩展空间——再加功能只能继续堆。

目标是把单页拆成**三页**，每页只做一件事，并腾出空间承载新功能（3D 关节、系统拓扑图）。

### 1.1 已确认的前置决策

| 决策 | 结论 | 影响 |
|---|---|---|
| 页面拆分 | 三页：初始 / 组态 / 监控 | 本设计主体 |
| **上位机运行环境** | **仅工控机**（有 GPU，不在 ARM 板上跑） | **不需要 WebGL 降级链** |
| 下发位置 | 下发目标**在监控页**（与观察同屏） | 组态页只管配置，不管下发 |
| 目标分辨率 | 1920×1080 | 不做移动端适配 |

### 1.2 术语

- **上位机界面**：本设计的主体，跑在工控机的浏览器里，是纯客户端
- **下位机**：ARM 板上的 Qt 程序，EtherCAT 主站 + `QWebSocketServer:9002`
- **安全条**：跨页常驻的顶栏，承载急停等安全操作

## 2. 范围

### 2.1 本子系统做什么

1. 把单页拆成三个页面容器 + 一个跨页常驻安全条
2. 实现页面切换（含 hash 同步、刷新后回到原页）
3. **把现有全部内容原样搬进监控页**，保证功能零回归
4. 按页面拆分 `app.js`（只做"按页分文件"，不做架构重构）
5. 保留 `index-legacy.html` 作为回归对照

### 2.2 本子系统不做什么

- **不做** WebGL 降级链（上位机仅跑在工控机，WebGL 恒可用）
- **不做** 组态页的具体内容（子系统 3）
- **不做** 3D 关节（子系统 2）
- **不做** 初始页的具体内容（子系统 4）
- **不做** 移动端 / 响应式（目标只有 1920×1080）
- **不引入** 前端框架（React/Vue）——离线环境，且现有代码是原生 JS
- **不改** `ws.js`（协议层与页面无关）
- **不改** 下位机（Qt）代码

> 本子系统交付后，三个页面中的**组态页与初始页是占位壳**，只有标题和一句说明；
> **监控页承载现有全部功能**。后续子系统各自填充自己的页面。

## 3. 页面结构

| 页面 | id | 职责 | 本子系统交付时 |
|---|---|---|---|
| 初始 | `page-boot` | 连接下位机、扫描结果、进入 | 占位壳 |
| 组态 | `page-config` | 系统拓扑与信号走向、关节参数、安全参数、负载标定 | 占位壳 |
| 监控 | `page-monitor` | **下发目标 + 3D 关节 + 波形 + 实时读数** | **现有全部功能** |

### 3.1 页面切换语义

- 三个 `<section class="page">` 全部存在 `index.html` 里，通过 `hidden` 属性切换
- **切页只切显隐，不重建 DOM**。理由：重建会销毁 3D canvas 与波形缓冲
- 当前页同步到 `location.hash`（`#boot` / `#config` / `#monitor`），刷新后回到原页
- **hash 为空时的默认页分两阶段**：
  - 本子系统交付时 → **监控页**。此时初始页与组态页还是占位壳，默认落过去会让人看到空页面
  - 子系统 4（初始页）交付后 → 改为**初始页**（那才是"初始"该有的含义）

  > 这条分阶段是有意的：默认页一旦改错，表现是"打开就是空白"，极易被误判成页面坏了。

### 3.2 页面间流转

```
初始 ──[连接成功]──► 组态 ──[进入监控]──► 监控
  ▲                    ▲                    │
  └────────────────────┴────────────────────┘
              安全条上的页面 tab 任意互跳
```

- 流转**不做强制拦截**：任何页面都能通过 tab 直接切到任何页面
- 原因是这是教学设备，学生需要来回对照看，强制向导会成为阻碍
- 「连接成功」的判定沿用现有逻辑：收到 `hello` 且 `state.bus` 非空

## 4. 常驻安全条（硬约束）

### 4.1 布局

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│ 初始 组态 监控 │ [关节1 · PHU-20H] │ EtherCAT●  控制权:上位机● │ ●运行使能 50Hz │ 失能 │ 急停 ESTOP │
└─────────────────────────────────────────────────────────────────────────────────┘
   导航（左）        身份                状态                  健康         操作（右）
```

从左到右四组：**导航 → 身份 → 状态 → 安全操作**。

### 4.2 控件清单

| 位置 | 控件 | 数据来源 | 约束 |
|---|---|---|---|
| 导航 | 页面 tab ×3 | `router.current` | 当前页高亮 |
| 身份 | 当前从站 + 型号 | `state.slaves` / `state.active` | 无关节时显示「无关节」 |
| 状态 | 总线状态徽章 | `link.connected` / `state.deviceConnected` / `state.simulated` | **四种状态必须区分**，见 4.3 |
| 状态 | 控制权徽章 + 请求/交还 | `state.owner` | 沿用现有 `renderTopbar()` 逻辑 |
| 健康 | 驱动状态（圆点+文字） | 当前从站遥测 `driveState` | 无遥测时显示「--」 |
| 健康 | 刷新率 | `state.rate.hz` | 无连接时显示「--」 |
| 操作 | 失能 | `link.command('disable')` | **恒可用** |
| 操作 | 急停 | `link.command('estop')` | **恒可用，视觉最突出** |

### 4.3 总线状态必须区分四种情况

现有 `renderTopbar()` 已经做对了，**必须原样保留**：

1. 未连接下位机
2. 已连下位机 · 设备未连接
3. ⚠️ 仿真数据（非真机）——**最醒目**
4. `<总线名>` 已连接

把「连上下位机」和「下位机连上设备」混为一谈，会让人以为关节已就绪（尤其仿真时数据看着和真机一样）。

### 4.4 不可违反的约束

- **急停与失能不受控制权和当前页面限制**，任何页面任何状态下都可点
- 安全条是**唯一的 DOM 实例**，三个页面共用，不重复创建（重复创建会导致状态不同步）
- 安全条**高度固定 52px**（内容不换行、不随窗口宽度变化而变高），页面内容区从它下方 52px 处开始
- 急停必须保持**视觉上最突出的元素**，任何新增装饰不得与它竞争注意力
- 三个页面共用同一个安全条 DOM 节点，切换页面时**不重新渲染**安全条

## 5. WebGL 与图形能力

上位机**只在工控机运行**，WebGL 视为恒可用。因此：

- **不实现**降级到 2D 的路径
- 保留一条最小兜底：创建 `WebGLRenderer` 失败时，在 3D 区域显示一行文字提示（「此环境不支持 WebGL」），**不白屏、不抛异常中断后续脚本**
- `prefers-reduced-motion` 仍要尊重：关掉自动旋转与脉冲，但保留 3D 渲染本身

> 原「方案 A：2D SVG 姿态盘」在设计层面**放弃**。
> 若后续需要「2D 视图」开关，另立需求，不在本设计范围内。

## 9. 实现后记（与本文的差异）

外壳落地后，组态页与初始页也一并实现了。以下几处与上面写的不一致，以实现为准：

   现在它自带 `app-legacy.js` / `ws-legacy.js` / `chart-legacy.js` / `anim-legacy.js` 四个冻结副本。
   **代价是四份重复代码**；若不打算再用它做回归对照，可整体删除。
3. **组态页与初始页不做 WebGL 相关处理**。§5 已说明上位机只在工控机跑，但组态页的拓扑图是
   纯 SVG，与图形能力无关，连"最小兜底"都不需要。
4. **新增一条本文没写的东西**：下发目标后在安全条上亮「运动中」脉冲徽章，跨页可见、可点击跳回。
   按用户决定**不做硬锁**（堵转时关节可能永远不"完成"，锁死会把人困住），只做提醒。
5. **发现并修复了一个协议缺口**（不在本文范围，但影响初始页的"扫描到的从站"）：
   `hello` 只在握手时下发一次，而下位机 `onSlavesDetected` 只存本地、不推送 ——
   客户端若比扫描更早连上，会永远停在「无关节」。
   现已在 `ControlServer` 增加 `sendSlaveList()`，网页侧 `hello` 与 `slaves` 推送
   收敛到同一个 `applySlaves()`。

## 10. 开场画面（后续变更）

初始页从"导航里的一页"改成了**启动时一次性出现的覆盖层**：

- 打开页面即显示，连接成功后自动过渡进正式界面，之后**永久摘除**
- 导航里只剩 `组态 / 监控` 两项 —— 开场画面不是"一页"，不该出现在导航中
- 连接步骤做成三段进度（连接下位机 → 握手 → 扫描从站），逐步点亮，
  既是开场动画也是真实状态显示

**三条必须守住的约束**（都不是体验问题，是安全问题）：

1. **中途断连绝不重新弹出。** 它是"启动时那一次"，不是"未连接状态"的显示。
   断连时弹回来会盖住急停和整个操作界面。
2. **连不上时必须放行。** 7 秒兜底后强制进场，绝不能把人永久挡在开场画面外。
3. **必须有回到连接界面的入口。** 否则开场画面消失后就再也换不了下位机地址。
   现在挂在安全条左侧的关节名上（可点击）。

另：连不上 4 秒后才滑出地址表单 —— 开场就被表单占满很丑。

### 10.1 改为手动点击进入

原本是"连上后自动进场"，后改为**由人点击「进入」按钮**才进正式界面。
理由：给操作员一个"连接状态我看过了、我准备好了"的确认动作，
比被自动推进去更符合试验台的使用习惯。

代价与对策：**必须保证按钮最终一定出现**——连不上就永远进不去的话，比自动进场更糟。
所以连不上到 4 秒时，按钮降级为次要样式并改文案为「不连接，直接进入」：
进得去，只是不显眼。

另修一处：地址表单原先是"露出后不再收回"的置位逻辑，慢连时会一直留着，
连上之后还摆着地址框纯属噪音。改成由 `!connected && 已等够 4s` 纯状态驱动。

### 10.2 页面切换动画（整页翻动）

两页像一条带子上的两格一起平移：出页整页退出（-100%），入页整页跟进（+100%）。

**必须是整页位移。** 第一版只挪 3.2%，肉眼根本感知不到移动，看起来"就是切换"，
不像翻页 —— 翻页感来自位移的**量**，不是缓动的好坏。出页留在原地被盖住是"抽屉"，
两页一起走才是"翻页"。

入页前缘加一道投影带（72px 渐变，随页面平移、结束时淡到 0），
让新页像"压"在旧页上抬起来 —— 纵深的关键一笔。

**约束不变**：只用 translate，绝不用 scale / rotateY。理由见下。

### 10.3 为什么不能用 scale / rotateY

`chart.js` 用 `getBoundingClientRect()` 算画布分辨率，**而这个值受祖先 transform 影响**：

- 平移 → 宽高不变，安全
- 缩放 / 3D 旋转 → 量到变形后的尺寸；更糟的是动画结束后**布局尺寸没变**，
  `ResizeObserver` 不会再触发，画布**会一直是错的**，而且看起来只是"有点糊"，
  根本查不出来

另外页面容器要 `overflow: hidden` —— 整页滑出时不能把外层撑出滚动条。

### 10.4 收尾

`Router._settle()` 负责把上一次没跑完的过渡收掉。连续快速切页时若不收，
会留下一个**永远不隐藏的页面**盖在最上面，表现为"点不动了"。

### 10.5 开场 → 主界面入场（重叠式）

原来是**接力**：开场画面用 600ms 淡完，**才开始**主界面入场 —— 中间空一拍，
而且主界面本来就渲染在那儿，看到的是"淡出后它就在了"。

改成**重叠**：开场画面用 `170ms` 后主界面就开始装配（此时光圈刚放大到一半）。
- 光圈放大 9.5 倍 + 淡出（"穿环"），文字上浮退场
- 安全条从上方落下；当前页的卡片按序号依次上浮归位（延迟 .14s 起、每张 +60ms）
- `.pages` 在入场前 `visibility: hidden` —— 否则开场画面还没淡完，卡片就"跳"
  回动画起始位置，会出现一次明显跳变

同时停用了 `Anim.entrance()`：它在页面加载时跑，而那时整块主界面被开场画面盖着
根本看不见；GSAP 还会留下内联 transform 与 `.app-in` 那套 CSS 动画打架。

### 10.6 波形画布满尺寸的竞态（重要 bug）

**症状**：切回监控页时波形画布有时是空白的，`canvas.width/height` 停在 0，
但布局尺寸正常（1530x177）—— 从界面上完全看不出原因。**实测 2/3 概率复现。**

**根因有两条，叠在一起：**

1. 页面被 `display:none` 隐藏时，`ResizeObserver` 会带着 **0 尺寸**触发一次，
   `resize()` 照写就把 `canvas.width/height` 归零了；
2. 页面重新显示时，`ResizeObserver` **不一定会再触发** —— 所以那个 0 就一直留着。

**修法（两处一起，缺一不可）：**
- `chart.js` 的 `resize()`：尺寸为 0 时**直接返回**，不写 `canvas.width/height`。
  宁可保留上一次的尺寸（至少是"曾经正确"的），也不要归零。
- 把 `resize` 暴露为 `chart.resize()`，由 `Router.onChange` 在切入监控页时
  **显式调用**，不再只依赖 ResizeObserver。

另外读数区的字号自适应自身也挂着 `ResizeObserver`，可能在画布重测**之后**又改
一次布局（字号 → 网格行高 → 波形高度），把尺寸带偏约 8px。所以在 700ms 后再补
一次 `chart.resize()`。

**教训**：`ResizeObserver` 不是"尺寸一定会同步"的保证，隐藏／显示的往返尤其不可靠。
凡是靠自己测尺寸来渲染的东西（canvas、二分字号），都要有一条**显式的**重测路径。

### 10.9 又一个虚拟时间的坑（记下来）

验证滚动步骤时反复被误导：`getComputedStyle` 和截图都显示"当前行是暗的、

禁用后再采样像素，得到 当前行 220 / 已完成 83 / 未开始 84，与设计一致。

### 10.10 步骤节奏：每步最短停留 800ms

**用户反馈**："滚动效果没体现出来，估计是太快了"。诊断正确 —— 但根因不是"时长不够"，
是**没有节奏**：WebSocket 往往在几百毫秒内就全部连上，三步几乎同时变 done，
滚动根本没东西可滚。

修法：加 `STEP_DWELL_MS = 800`，每一步**至少停留 800ms**才允许推进。
用 `displayStep()` 把真实步骤号放慢成显示用的（只延迟推进，绝不跳过）。

**这是显示节奏，不是伪造状态**：真实状态照样即时生效，只是不让它瞬间跳到最后。
实测轨迹：`0→0→0→1→1→1→2→2…`（每格约 800ms）。

「进入」按钮也跟着等：连上后还要**等步骤滚完**才出现，否则点早了会把序列截断。
已连接状态下重新叫回连接界面时，步骤直接显示为完成，**不重放扫描动画**（那会是在骗人）。

### 10.22 表盘立体化 + 三维平滑缩放 + 全屏遮罩

**① 表盘做出深度**
不是靠堆阴影，是靠**凹槽**：表盘是一条**刻进面板的环形槽**，填充弧**嵌在槽里**。
光源统一从正上方来，所以：
- **槽底竖直渐变「上暗下亮」** —— 上半是槽壁挡出的阴影、下半受光。
  这是"凹"的关键，**反过来（上亮下暗）立刻变成"凸"**。
- 槽内外各一道细线（外沿暗、内沿亮），给出两条倒角边
- 填充弧比槽窄（7 vs 12），嵌在槽中间，自带同色发光
- 游标用**径向渐变画成球**（高光偏左上），不是纯色圆
- 顶部一道很淡的白色弧当玻璃反光
- 主色用 CSS 变量 `--gc` 传，发光/数字色都跟着它走

**② 三维平滑缩放**
不用 OrbitControls 自带的离散缩放，而是**逐帧把相机距离插值逼近目标值**
（`ZOOM_LERP=0.16`）。所以按按钮/滚轮是"滑"过去的。顺序有讲究：
**先动相机再 `controls.update()`** —— 后者按当前相机位置重算球坐标，先动它才认得。
另加 ＋/−/↺ 三个按钮，`zoomSpeed` 从 1 降到 0.62（默认速度在大屏上"一跳一跳"）。

**③ 全屏切换的跳变**
浏览器切全屏是**瞬时**的，画布尺寸瞬间跳变 + 一次重排，看起来是"闪一下"。
给容器重放一次 0.44s 的淡入（`opacity .3→1` + 轻微 scale）把这一跳盖住。

### 10.23 进出全屏的平滑（用户指的就是这一处）

用户澄清"界面切换不丝滑"指的是**进出全屏**。前一次只加了淡入遮罩，但那**盖不住
"模型突然变大/变小"** —— 画布尺寸一跳，模型在屏幕上的占比跟着跳，人能直接感知到。

补一个**镜头动作**：`Joint3D.settle()` 让镜头**先回拉 30%、再归位**（约 0.5s）。
配合遮罩（起点 opacity 压到 0.18、时长 0.52s），观感从"闪一下"变成"切过去并
自动对好焦"。

**为什么不能只靠淡入**：淡入解决的是"画面内容突变"，而这里变的是**尺寸关系**——
是空间感的变化，不是亮度变化。必须有一个**空间上的动作**去承接。

### 10.24 全屏的真正根因 + 仪表换回数字 + 版面清理

**① 全屏"突然变大"的真正根因**

淡入盖不住它，是因为**变的是尺寸不是亮度**。真正的机制是：
浏览器切全屏是**瞬时**的，画布高度一下子变成 3 倍多；固定 fov 时
`模型像素高度 ∝ 画布高 / 相机距离` —— 画布高翻 3 倍 = 模型瞬间放大 3 倍。

修法：**在同一帧把相机距离也乘上同样的倍数**（模型看起来和切换前一样大），
再让它滑回原距离。观感是"从小窗一路推进到全屏"。
按"高度突变 > 15%"识别而不是靠按钮回调 —— 这样 **Esc 退出全屏也走同一条路**。
（上一版加的 `settle()` 已撤掉，会和这个补偿叠加。）

**② 仪表换回数字 + 遥测挪到左栏**
用户要求。表盘那套（含立体化）整体删除，`js/gauges.js` 删除，
`fitReadouts()` 恢复（这一栏同时塞着三维、三个大数字、遥测表，字号必须能压下来）。

**★ 三维必须有保底高度**：它是 `flex:1`，读数区是 `flex:0 0 auto`。
不给下限的话，读数区的字号自适应会把它**挤成一条 50px 的缝**（实测）。
加 `min-height: 190px` 后，读数区只能在剩下的空间里自适应 —— 这正是想要的优先级。

**③ 版面清理**：删掉 [操作]/[目标] 两张卡的标题、操作卡里的"行程"块、
目标卡下方那句「当前控制权在下位机…」（安全条上的控制权徽章已经说得很清楚，重复）。
`cmdHint` 只保留"请先勾选「已确认现场安全」"。

**④ 差点漏掉的一处**：删除表盘样式时，脚本把**「两行网格」那一整块**（`.layout` 的
`grid-template-rows` + 卡片 `grid-row` 分配）连带删掉了。于是回落到 app.css 里
**为三行布局写的老规则**（auto 顶栏行 + 3fr + 2fr，而顶栏行早已删除）——
第一行是空的 auto，波形只拿到 2/5（277px 而不是 353px）。
**按区块标题做区间删除时，要确认区间内没有别的东西。**

### 10.25 左栏改并排两栏 + 负载提示只留失败

**① 三维下方并排两栏**
原来是上下堆（3 个大数字 → 遥测表）。堆叠的问题：大数字的字号自适应会**吃满高度**，
把遥测挤出可视区（用户反馈"温度那些挤没了"）。

改成并排：左＝三个大数字，右＝遥测（改成"标签｜值"两列的单列表 —— app.css 里
是 4 列一行放两对，在这么窄的栏里会挤成一团）。字号上限从 34px 收到 26px。

**效果很直接**：三维从 190px 涨到 **336px** —— 省下的正是原来遥测占的那一整段高度。

**② 负载提示只留失败**
用户反馈操作卡里那行绿色文字（"已预设 X N·m…点「下发目标」时施加"）不需要。
改成 `ok=true` 一律清空，只有 `ok=false` 才落字。

**但失败必须留** —— 写失败时制动器毫无反应，界面不提示会把排查引向完全错误的方向
（这个项目在别处吃过同类亏）。所以不是删掉整个提示，是删掉"一切正常"那部分。

### 10.26 新增「历史数据」页（与监控页完全分开）

用户定的架构：**实时波形只画本次运行，历史与对比放独立页面**，互不干扰。

**存储**（`js/history.js`，IndexedDB）
- 一次运行一条记录，**名称是主键**，重名覆盖（用户定的）。默认名称 = 保存时间
- 为什么不用 localStorage：一次约 9000 个数（3 轨迹 × 3000 点），localStorage 只有
  5~10MB 且**同步** —— 50Hz 刷新下写一次会卡住整个界面
- 上限 60 条，超了删最旧的
- **无痕/禁用存储时 `open()` 会失败** → 返回 null，上层当"没有历史功能"，不把页面带崩
- 存在**运动结束时**（图表自动收尾），不是下发时 —— 下发时缓冲还是空的

**分色规则（最容易糊的一处）**
> **运行 = 颜色**（8 色调色板）    **轨迹 = 线型**（位置实线 / 速度虚线 / 力矩点线）

实时波形图是"轨迹=颜色"（位置青/速度绿/力矩琥珀）。对比场景的主角是**运行之间的
差异**，颜色必须留给运行。三条轨迹最多三种线型，够用且不冲突。再配**轨迹筛选**，
只留一条轨迹时就是 N 条纯色线 —— 最干净。

**两条不能省的规则**
- 时间轴按 **t=0 对齐**，不各自缩放到满宽。缩放会把"响应慢"也拉成"响应快"——
  而对比要看的就是谁快谁慢。
- 每个窗格 Y 量程取**所有已选运行的并集**，不各自缩放 —— 各自缩放会让差很多的
  曲线看起来一样。

**★ 窗格标签旁的示意必须用中性色**：一开始画了个轨迹色的 ■，但图上的线是
"按运行上色"的，那块颜色在图上根本不存在 —— 会误导。改成画一段**线型示意**
（中性灰 + 对应的虚实模式），只表达"这条是实线还是虚线"。
