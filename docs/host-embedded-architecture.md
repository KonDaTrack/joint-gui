# 上位机 / 下位机 分工架构设计

**日期**：2026-09-16
**状态**：设计已确认，待实现

## 1. 背景与约束

### 硬约束：EtherCAT 总线只能接一台机器

关节的 EtherCAT 总线**物理上只能接到上位机（PC）或下位机（ARM）之一**，不可能两台都直接控制。
但需求是**两边都能操作**——本地（设备旁）和远程（PC）都要能控制。

→ **因此必须有一层网络协议**：接总线的那个当主站，另一台通过网络访问。
这是架构的起点，不是可选项。

### 选定拓扑：ARM 当主站

```
关节 ──EtherCAT──► ARM 板（主站 + 本地界面 + 网络服务）   ← 唯一接总线的
                        ▲
                        │  TCP / WebSocket
                        ▼
                  PC 上位机（远程界面，纯客户端）        ← 不碰总线
```

**为什么选 ARM 当主站**：
- ARM 就在设备旁，本地界面不受网络影响，断网也能操作
- 实时性：ARM 本地跑控制回路，不依赖网络
- PC 端变成纯客户端 → 可以自由选择技术（QML 或 Web），不受实时性约束

## 2. 控制端与看门狗

> **本节曾被"控制权仲裁"占满**（本地/远程状态机、请求-授权、切换即失能）。
> 那套东西的前提是"两个操作者"——下位机有本地界面，PC 也有界面。
> **下位机改成无窗口启动之后，这个前提没有了**，仲裁整个删掉。
> 老实现在 git 里（`2bf50e3` 之前），要回看可以去翻。

### 2.1 只有一个控制端

下位机默认**无窗口**（`--ui` 才显示本地界面，只作调试用）。设备侧不再有人操作，
所以现在只有上位机这一个控制端 —— 相应删掉的是：

- 本地/远程归属状态机、`requestControl` / `releaseControl`
- 下位机端「允许上位机接管控制」开关
- "切换即失能"
- 两端的控制权徽章，以及"无控制权一侧置灰"

留着它们的代价是：网页每次用之前都得先点一下「请求控制权」，而那个请求还得
有人在板子上勾个框才批 —— 板子常常就在机柜里，没人会去点。

### 2.2 保留下来的是看门狗 ⚠️ 最重要

仲裁没了，但"人不在 / 网断了要自己停"这一条**必须留**，而且比原来更重要：
**本地已经没有界面了**，上位机一掉，就再也没有任何人能发出停止命令。

两条触发路径，都要有：

| 触发 | 行为 |
|---|---|
| WS 连接断开 | 立即失能所有轴 + 撤载 |
| 心跳超时（>1s 没收到 `heartbeat`） | 同上 |

**为什么两条都要**：正常关闭（关页面、关窗格）会走前者；而**网线被拔、
网页卡死**这种 TCP 半开的情况 `disconnected` 不会触发 —— 只有心跳能兜住。

★ 所以心跳是**只要连着就一直发**，不再是"仅持有控制权时发送"。
不发的话下位机那边的 `lastHeartbeatMs_` 恒为 0，看门狗永远武装不起来 ——
保护会**静默失效**，界面看起来一切正常。这条是这次改造里最容易改错的地方。

（与既有遥测看门狗同思路：500ms 无遥测即判定连接断开。）

### 2.3 急停

`estop` 不受任何限制，任何时候都能发。安全命令不该被权限挡住。

## 3. 网络协议

### 3.1 传输

- **起步：WebSocket + JSON**（调试直观、Qt 客户端/浏览器都支持）
- 若带宽/延迟不够再考虑二进制帧
- Qt 侧用 `QWebSocketServer`（Qt Network 模块自带，**无需引入新依赖**）

### 3.2 下行（ARM → PC）：遥测

**必须降频**。当前是 500Hz × N 从站原始数据直接画；浏览器/远程客户端不需要这个频率。

- **降频到 30~60Hz**（客户端渲染帧率）；由 ARM 侧聚合/抽稀后下发
- 每组遥测含：从站号、时间戳、位置、速度、力矩、温度、状态字、故障码、驱动状态、是否越限
- 附带 **各从站型号/额定力矩**（界面显示需要）

> 附带好处：500Hz 原始数据噪声大（速度差分、力矩纹波），降频聚合后曲线反而更平稳。

### 3.3 上行（PC → ARM）：命令

| 消息 | 说明 |
|---|---|
| `heartbeat` | 心跳。**连接期间一直发**（200ms）—— 它是下位机看门狗唯一的输入 |
| `selectSlave` | 切换当前从站 |
| `enable` / `disable` / `quickStop` / `faultReset` | 基本操作 |
| `setMode` / `setTarget` | 模式与目标。`setTarget` 可带 `loadNm` —— 见下 |
| `stopMotion` | 停止运动。**必须与 `setTarget` 分开**：负载链挂在"下发目标"上，共用的话点停止会先写一次负载 |
| `homing` / `moveToZero` | 归零 / 回0 |
| `setLoad` | 预设磁粉制动器力矩（N·m）。**只记住，不施加** |
| `releaseLoad` | 立即松开负载（写 0），不动关节 |
| `estop` | 急停。不受任何限制 |

> 没有 `requestControl` / `releaseControl` 了 —— 上位机是唯一控制端（见 §2）。

#### 负载（磁粉制动器）

走 **RS485 → Modbus → 0-10V**，与关节的 EtherCAT 是**两条独立链路**：不受"当前从站"影响。

- 标定：**50 N·m ↔ 10V**（模块单位 mV，即 `mV = N·m × 200`）。客户端算的电压**只用于显示**，
  ARM 一律用 `torqueNm` 自己换算，不信客户端传的电压
- 流程：网页设好值（`setLoad`，仅预设）→ 点「下发目标」→ ARM **先写负载、确认模块应答成功**，
  再发运动指令 → **运动结束时自动清零**
- **写失败则拦住运动指令**（避免产出"看着正常、其实空载"的实验数据）。
  但预设为 0 时整条链跳过、根本不调 `modbus_ao`，所以工具坏掉不会把关节锁死
- 堵转（下发后关节一直没动）**不设超时**，负载保持；要撤载用「松开负载」或失能/急停
- 回报 `loadState { state, presetNm, torqueNm, volt, note }`，`state` 取
  `preset / writing / applied / cleared / failed`。`torqueNm = -1` 表示"外设实际状态未知"，与 0 含义不同
- `hello` 里带 `load` 字段：否则网页重连后滑块归 0，而制动器可能正咬着上一个值

> ⚠️ 进程被 SIGKILL / 板子掉电后，**AO 模块会保持最后写入的电压**（模块自身没有看门狗）。
> 现场应急松开：`~/rs485/modbus_ao -c 4 -v 0 -t 300`
>
> ⚠️ 撤载瞬间负载消失会导致关节窜动/重力下垂，这是该测试方法的固有特性。**带载首次试必须有人守在急停旁。**

### 3.4 安全边界

**PC 端不能绕过 ARM 的安全逻辑**。以下全部在 ARM 侧强制执行，不依赖客户端：
- ±170° 行程限位
- 遥测看门狗
- 控制权校验
- 心跳超时收回

客户端只负责"发意图"，**判断与拦截一律在主站**。

## 4. 职责划分

| | 下位机（主站，**默认无窗口**） | 上位机（浏览器） |
|---|---|---|
| EtherCAT 主站 | ✅ | ❌ |
| 实时控制回路 | ✅ | ❌ |
| 安全逻辑（限位/看门狗） | ✅ **权威** | 只显示 |
| 本地界面 | 仅 `--ui` 时（调试用） | — |
| 界面 | — | ✅ 全部在这里（监控/历史/终端三页） |
| 网络服务端 | ✅ `QWebSocketServer` :9002 | — |
| 网络客户端 | — | ✅ |

**上位机侧的技术选型（QML / Web）不影响本协议** —— 协议是技术无关的。
现在是 Web（`web/`），因为要浏览器/多端访问。

**界面全部搬到上位机之后，下位机默认不建任何窗口**（`src/main.cpp`）。
它开机就自动检测总线并连上，不需要任何人在板子上点一下。

## 6. 未决事项

1. **协议细节**：错误码、版本协商（JSON 字段本身已稳定）
2. **是否支持多 PC 同时连接**：现在仍是**单客户端**（后来的会被拒）。
   控制权仲裁删掉之后，多客户端需要的是**互斥**而不是归属协商 —— 改法不同，
   要想清楚再动。
3. **下位机上的急停**：本地界面默认不存在，急停只剩网页上那一个
   （外加用户自行加装的硬件急停）。这是有意的取舍，但值得在交付时讲清楚。
