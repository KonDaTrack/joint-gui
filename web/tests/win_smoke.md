# 终端页 · Windows 手测清单

`web/server/pty_win.py`（ConPTY）是**唯一没法在开发机上验证**的一段
—— 它只在 Windows 上跑得到，Linux 上连 import 都走不到那条分支。
后端和前端其余部分都有自动测试（`term_client.js` / `ui_term.js`），只有这里是人工。

跑完请把**哪一步不对**、`serve.py` 控制台的原话、浏览器 F12 控制台的报错发回来。

## 前置

- Windows 10 **1809（build 17763）以上**（`winver` 里看）。更老的版本没有 ConPTY，
  终端页会显示"当前平台不支持终端" —— 那是预期行为，不是 bug。
- Python 3.9+（`python --version`）。**不需要 pip 装任何东西**。
- 装 Python 时若没勾 "Add Python to PATH"，用 `py serve.py` 代替。

## 0. 起服务

```
cd <仓库>\joint-gui\web
python serve.py
```

**期望**：打印两行（`界面 http://localhost:8080/` 和 `终端 ws://localhost:8080/term`），
且**没有** `警告：当前平台不支持终端`。

> ★ 别用管理员身份起。终端里开出来的就是当前用户的 shell。

## 1. 基本

| 步骤 | 期望 |
|---|---|
| 浏览器打开 `http://localhost:8080` | 开场画面 → 出现扫描结果 → 点「进入」 |
| 点导航「终端」 | 出现提示符（cmd 的话形如 `C:\...>`） |
| 敲 `dir` 回车 | 列出文件，光标位置正确 |
| 敲 `echo 中文测试` | 中文显示正常，**不是乱码** |
| 敲 `chcp` | 显示当前代码页（默认 936） |

若第 4 条乱码：这是编码问题，记下 `chcp` 的值，先别改代码。

## 2. 切分与互相独立

| 步骤 | 期望 |
|---|---|
| 点「左右切分」 | 变成两格，右边出现**新的**提示符 |
| 左边 `cd \Windows`，右边 `cd \` | 两边的 `cd` 互不影响（各自独立 shell） |
| 右键任意一格 | 弹出菜单：左右/上下切分、最大化、关闭窗格 |
| 点「上下切分」 | 变成三格，嵌套正确（不是把整个页面切成上下两半） |
| 拖中间那条分隔条 | 两边宽度跟着变；松手后终端内容重新排布 |
| 点「最大化」再点一次 | 该格吃满，再点还原回三格 |

## 3. 尺寸真的传到了 ConPTY

切大左边那格，然后在**左边**敲：

```
mode
```

**期望**：`CON` 那一段的 `Columns:` / `Lines:` 跟着窗格大小变了
（这是验 `ResizePseudoConsole` 有没有被调到）。

## 4. 收尾

| 步骤 | 期望 |
|---|---|
| 在某格敲 `exit` | 该格盖一层「这个 shell 已退出」+ 一个「重连」按钮 |
| 点「重连」 | 出现新提示符，**不是**旧的残留画面 |
| 关掉一格（三格→两格） | 剩下的格子尺寸自动铺满，内容重新排布 |
| 只剩一格时看右键菜单 | 「关闭窗格」是**灰的** |
| **任务管理器**里找 `cmd.exe` | 关掉的窗格对应的进程**已消失**（不是残留） |
| 刷新页面 | 回到一格，是新 shell |

> 最后一条（进程不残留）是这段代码最容易出错的地方，请务必看一眼。

## 5. 如果出错

按现象分类，这些信息最有用：

| 现象 | 需要的信息 |
|---|---|
| `serve.py` 起不来 | 控制台的完整 traceback |
| 起得来但终端页空白/转圈 | `serve.py` 控制台有没有 `[term] ... 打开终端`；浏览器 F12 的报错 |
| 有提示符但敲键无反应 | 是"完全没反应"还是"回显但回车无效" |
| 关不掉 / 进程残留 | 任务管理器里残留的是什么进程名 |
| 报 "CreatePseudoConsole 失败：HRESULT 0x........" | 把那个 16 进制码原样发回来 |
